## 1. Core Principles & Boundaries

1. **The Hero Experience**:
   - The user inputs natural language changes (e.g. *"Budget is now 2 lakh and the date moved two weeks earlier"*).
   - Zero blind recalculation or silent overwrites. The system shows exactly what changed (deltas, deadline shifts, warnings) and computed tradeoff options.
2. **Code Computes, LLM Explains**:
   - The LLM parses user text into validated operations (`Op[]`) via `/api/change`.
   - Domain code applies ops to a shadow clone of state, runs `buildPlan`, and executes `diffPlans` and `generateScenarios`.
   - The LLM narrates the impact and recommends the best option via `/api/advise`.
   - Rupee amounts, task dates, and savings figures come 100% from deterministic domain code.
3. **Data Safety & State Preservation**:
   - Completed tasks (`completedTasks`) and locked categories (`lockedCategories`, `lockedBudgetLines`) survive replans intact.
   - Every applied replan pushes a complete snapshot to the undo history stack (`history`, cap 20).
   - If an AI call fails, the current plan remains untouched, and a friendly retryable error message appears.
4. **Accessible Modal & Keyboard Flow**:
   - Fully accessible modal (`role="dialog"`, `aria-labelledby`, `aria-modal="true"`, focus trap, Escape key closes).

## 2. Component Specifications

### 2.1 Change Bar (`src/components/replan/ChangeBar.tsx`)
- **Placement**:
  - Docked at the bottom of the left workspace column in `src/app/page.tsx`, persistent and visible across all active tabs (`intake`, `budget`, `timeline`).
- **Input & Quick Suggestion**:
  - Input field with placeholder: *"Change anything (e.g. 'Budget is now 2 lakh and event moved 2 weeks earlier')..."*.
  - Hero demo suggestion chip: `"Cut budget to ₹2 Lakh & move date 2 weeks earlier"`.
  - Submit button with loading spinner state (`aria-busy`).
- **Interaction Logic**:
  1. User submits natural language change.
  2. Submits to `POST /api/change` with current state.
  3. If response contains `clarification`:
     - Displays clarification message in an accessible inline callout / toast without touching the plan.
  4. If response contains `ops`:
     - Clones current state and applies ops via `applyOps(state, ops, today)`.
     - Recomputes proposed plan via `buildPlan(nextState, today)`.
     - Computes diff via `diffPlans(currentPlan, proposedPlan)`.
     - Computes 2–3 deterministic tradeoff scenarios via `generateScenarios(nextState, proposedPlan)`.
     - Calls `POST /api/advise` with `{ state: nextState, diff, scenarios }`.
     - If `/api/advise` succeeds, uses LLM narrative; if it fails/times out, uses pure domain fallback narrative so the user can still review and apply the diff!
     - Launches `ReplanDiffModal`.

### 2.2 Replan Diff Modal (`src/components/replan/ReplanDiffModal.tsx`)
- **Structure**:
  - **Header**:
    - Title: "Plan Revision & Impact Analysis".
    - Badge indicating provenance of advice: `AI estimate` / `Derived`.
    - Close (✕) button.
  - **Advisor Summary Banner**:
    - High-level explanation of the impact (e.g., budget deficit, critical path bottlenecks).
  - **Sectioned View**:
    - **1. Budget Impact (Deltas)**:
      - Category-by-category comparison: `Previous Amount` → `New Amount` with delta indicator (`+₹X` or `-₹X`).
      - Visual tags for locked categories that remained preserved.
    - **2. Schedule & Timeline Impact**:
      - Tasks with changed deadlines and days shifted (e.g. `14 days earlier`).
      - Compressed schedule warning indicator if applicable.
    - **3. Warnings & Health Changes**:
      - Newly triggered warnings (e.g. `COMPRESSED_SCHEDULE`, `LOW_PER_GUEST_CATERING`).
      - Resolved warnings (green badges).
    - **4. Tradeoff Scenarios (Options A, B, C)**:
      - 2–3 scenario cards generated by `generateScenarios`:
        - Card 1: Direct Change (as requested).
        - Card 2: e.g. Trim Guest Count (keeps per-guest food/decor quality high).
        - Card 3: e.g. Rebalance & Simplify Priorities (cuts low-priority lines).
      - Displays computed `tradeoff`, `why`, and `savingsAmount`.
      - Highlights `recommendedScenarioId` with an "Advisor Recommendation" badge.
      - User can select which scenario to apply via intuitive radio card selection.
  - **Footer Actions**:
    - Primary Button: "Apply Selected Plan" (applies chosen ops, pushes to history, closes modal).
    - Secondary Button: "Discard & Keep Current Plan" (closes modal with 0 changes).

### 2.3 Undo & History Integration
- When a replan or scenario is applied:
  - Calls `applyOpsAction(chosenOps, label)`.
  - Pushes an undo entry with a descriptive label (e.g., `"Replan: Cut budget to ₹2L"`).
  - The Header "Undo" button lights up with snapshot count and restores previous plan in one click.
